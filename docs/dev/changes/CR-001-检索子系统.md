# CR-001 检索子系统重设计

- 状态:已完成

- 关联契约:`docs/dev/任务书.md`;实现细节见 `docs/dev/架构说明.md`

## 1. 变更原因

原检索只有子串字面匹配;查询永远是识别出的植物名,界面没有自由文本输入,召回没有可提升空间。

## 2. 影响范围

- 新增:`retrievers.py`、`router.py`、`eval_retrieval.py`、`scripts/build_eval.py`、`tests/`、`data/eval_queries.jsonl`
- 修改:`config.py`、`rag.py`、`tools.py`、`agent.py`、`app.py`、`kb/植物养护手册.txt`、`requirements.txt`、`README.md`、`.gitignore`
- 生成物:`models/chunks.json`、`models/emb_qwen3_0.6b.npz`、`指标/M0_*.md`、`指标/检索对比表.md`、`指标/检索错误案例.md`、`指标/eval.db`
- 文档:任务书 §11 历史里程碑、`架构说明.md`、README 检索子系统章节、本 CR

## 3. 方案要点

- 知识库拆成 20 植物 × 7 小节,共 140 chunks;
- BM25(jieba + 汉字级补偿)、稠密向量(Qwen3-Embedding-0.6B)、RRF 融合;
- 特征路由 + 检索质量回退(CRAG-lite);
- 产品支持纯文字 / 纯图片 / 图片+追问,本地路线零 API;
- 120 条标注评测集与 5 组对照。

## 4. 验收标准与结果

**自动化测试**:`python -m unittest discover -s tests` → 15 个用例全绿。

**指标(120 题,Recall@5 / MRR)**

| 配置 | Recall@5 | MRR |
|---|---|---|
| naive | 0.682 | 0.433 |
| bm25 | 0.691 | 0.646 |
| dense | 0.518 | 0.445 |
| hybrid | 0.691 | 0.675 |
| adaptive | 0.927 | 0.804 |

- M0 判据:两路差距 0.173、互补 43.6%,通过;
- M1:hybrid ≥ 单路最好值 − 0.02;
- M2:adaptive ≥ hybrid − 0.02,中位延迟 ≤ hybrid × 1.1;
- 手工场景:纯文字问答、图片 + 本地路线、图片 + 追问、库外问题提示,均通过。

**未验证**

- 真实植物图片的识别准确率(仓库缺 `data/`、`test_set/` 图片);
- `api` 路线完整链路(需要 `.env` 中的 Key;带图时会调用 2 次 LLM:识图 + 生成建议)。
