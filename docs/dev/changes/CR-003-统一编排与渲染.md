# CR-003 统一编排与渲染

- 状态:提案(待评审,未实施)
- 日期:2026-11-25
- 依赖:无
- 建议顺序:1/5(架构重整第一批)

## 1. 变更原因

`app.run` + `app.build_result` 与 `agent.agent_handle` 是两套并行的编排/渲染逻辑;`app` 还绕过 `agent` 直接调用 `tools`。两套逻辑会随需求变化而漂移,是当前最主要的耦合点。

## 2. 影响范围

- 修改:`app.py`、`agent.py`
- 不动:`retrieval/`、`config.py`、CV 脚本、评测产物
- 文档:README 无需改命令;在 `架构说明.md` 与变更索引追加实施记录

## 3. 方案要点

- `agent.agent_handle(img_path=None, route="api", question=None) -> str` 成为**唯一编排入口**;
- 把"本次用时/路线"页脚从 `app` 移入 `agent`(计时逻辑随之移动,文案保持现状);
- `app.run(img, route_label, question)` 只做三件事:参数归一、调用 `agent.agent_handle`、异常转"出错了";
- 删除 `app.build_result`,删除 `app` 对 `tools` 的直接依赖;
- 保持返回 Markdown 字符串,不引入结构化返回(避免 UI 改造)。

**不做**:不改 Gradio 布局与 JS;不改 prompt;不改检索与路由;不改错误文案。

## 4. 验收标准

- `grep -n "build_result" app.py` 无结果;
- `app.py` 不再 `import tools`;
- 三条路径输出与改造前一致:纯文字、纯图片、图片+追问(用同一输入对比改造前后 Markdown);
- `python -m unittest discover -s tests` 15 个用例全绿;
- `python -m retrieval.eval` 五组指标与改造前一致
  (0.682 / 0.691 / 0.518 / 0.691 / 0.927);
- 空输入提示、无 Key 报错、库外问题提示均保持原样。

## 5. 回滚方案

`git revert` 单个提交,恢复 `build_result` 与 `app.run` 原逻辑。无数据/缓存副作用。

- 验收:纯文字(别名)、库外、空输入、无 Key、图片+追问五条路径 Markdown 与改造前逐字一致(仅耗时数字归一);15 个测试全绿;五组 Recall@5 = 0.682/0.691/0.518/0.691/0.927,与改造前一致。
