# CR-004 配置分层

- 状态:提案(待评审,未实施)
- 日期:2026-11-25
- 依赖:无(可与 CR-003 并行)
- 建议顺序:2/5

## 1. 变更原因

根 `config.py` 同时承载三类配置:环境与 API、CV 路径、检索超参与缓存路径。检索参数被所有模块可见,根配置 fan-in 过高;检索包无法独立说明自己的配置契约。

## 2. 影响范围

- 新增:`retrieval/settings.py`
- 修改:`config.py`、`retrieval/rag.py`、`retrieval/retrievers.py`、`retrieval/eval.py`、`tools.py`(去掉 `cfg.TOP_K` 依赖)
- 不动:CV 脚本、`agent.py`、`app.py`
- 文档:`架构说明.md`、README 目录树(新增 settings.py)

## 3. 方案要点

根 `config.py` 只保留:
- `BASE_DIR`、`.env` 加载、`DEEPSEEK_API_KEY`、`BASE_URL`、`MODEL`、`require_api_key()`;
- CV 路径:`DATA_DIR`、`TEST_DIR`、`CKPT`、`NUM_CLASSES`。

新增 `retrieval/settings.py`(只依赖 `config.BASE_DIR`):
- 模型:`EMBED_MODEL`、`EMBED_FALLBACK`;
- 缓存:`EMBED_CACHE`、`CHUNKS_CACHE`(CR-005 再改目录);
- 知识库:`KB_DIR`(仅检索使用);
- 评测:`EVAL_DIR`、`EVAL_DB`;
- 检索参数:`TOP_K`、`FUSE_TOP_N`、`RRF_K`、`COVERAGE_THRESHOLD`、`DENSE_COS_THRESHOLD`、`ANSWER_COS_THRESHOLD`、`CHUNK_MIN_LEN`。

调用方调整:
- `retrieval/*` → `from . import settings as st`,`from config import BASE_DIR`(仅 settings);
- `tools.py` 不再读取 `cfg.TOP_K`;把"至少取 TOP_K 条"的策略下沉到 `rag.retrieve*` 内部(`topk = max(topk or 0, settings.TOP_K)`),产品层不再感知检索参数。

**不做**:不引入 pydantic/dataclass 配置框架;不做环境变量覆盖所有常量。

## 4. 验收标准

- `grep -nE "TOP_K|RRF_K|EMBED_|COVERAGE_THRESHOLD|CHUNK_MIN_LEN" config.py` 无结果;
- `python -c "import config, retrieval.rag, retrieval.eval"` 成功;
- `grep -rn "cfg.TOP_K" --include="*.py" .` 无结果;
- 测试 15 绿;五组评测指标与改造前完全一致;
- 界面三条路径正常。

## 5. 回滚方案

删除 `retrieval/settings.py`,把常量并回根 `config.py`,`git revert` 单提交。
