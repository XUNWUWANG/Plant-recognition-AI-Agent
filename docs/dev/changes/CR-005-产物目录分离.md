# CR-005 产物目录分离

- 状态:提案(待评审,未实施)
- 日期:2026-11-25
- 依赖:CR-004(配置分层)
- 建议顺序:3/5

## 1. 变更原因

当前目录把"可交付权重"与"可重建缓存"混在 `models/`,把 CV 与检索结果混在 `指标/`,把评测集与训练数据混在 `data/`。识别成本高,也容易误提交大文件。

## 2. 影响范围

- 移动(生成物):`models/chunks.json`、`models/emb_qwen3_0.6b.npz` → `models/cache/`
- 移动(评测集):`data/eval_queries.jsonl`、`data/eval_candidates.jsonl` → `data/eval/`
- 移动(检索指标):`指标/M0_*.md`、`指标/检索对比表.md`、`指标/检索错误案例.md`、`指标/eval.db` → `指标/retrieval/`
- 修改:`retrieval/settings.py`(路径)、`scripts/build_eval.py`(默认路径)、`retrieval/eval.py`(默认输出/DB)、`.gitignore`、README
- **不动**:`compare.py` 及其输出 `指标/对比表.md`、`指标/公平复测.txt`(任务书"不动"范围,保留在 `指标/` 根作为历史 CV 产物)

## 3. 方案要点

- `models/` 只放交付资产:`best.pt`、`classes.json`、`hist_*.json`;
- `models/cache/` 放 `chunks.json`、`emb_qwen3_0.6b.npz`,并在 `.gitignore` 忽略;
- `data/eval/` 放两份 jsonl,`.gitignore` 的例外规则同步改到该目录;
- `指标/retrieval/` 放全部检索评测结果;`指标/` 根保留 CV 旧产物,不再新增;
- 历史文档(CR-001、CR-002)中的旧路径不改,作为当时记录;当前文档(README、`架构说明.md`、本 CR)使用新路径。

**不做**:不移动 `train.py`/`compare.py` 的输出路径(避免修改 CV 脚本);不重命名 `指标` 目录。

## 4. 验收标准

- `python -m retrieval.rag --rebuild` 在 `models/cache/` 生成两个缓存文件;
- 再次运行 `python -m retrieval.rag --stats` 命中 chunks 缓存;`python -m retrieval.eval` 第二次运行命中向量缓存,不重新编码;
- 五组指标与改造前一致;
- `git status` 不出现 `models/cache/*`、`data/eval/*`(若按要求忽略评测集)或明确只提交 jsonl;
- `git diff compare.py` 为空;
- README 中评测产物路径与命令行输出一致。

## 5. 回滚方案

把文件移回原路径,恢复 `settings`/`eval`/`build_eval`/`.gitignore`,删除空的 cache 目录;必要时 `python -m retrieval.rag --rebuild` 重建。
