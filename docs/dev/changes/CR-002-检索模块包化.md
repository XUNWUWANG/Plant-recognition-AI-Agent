# CR-002 检索模块包化

- 状态:已完成
- 日期:2026-11-25
- 关联契约:`docs/dev/任务书.md` §14 第 9 条
- 前置:`CR-001`(检索子系统功能已完成并验收)

## 1. 变更原因

根目录同时承载 CV 训练、产品编排、检索三条职责;检索子系统是一个内聚模块,继续平铺会让根目录膨胀,模块边界不清。

## 2. 影响范围

- 移动:`rag.py`、`retrievers.py`、`router.py` → `retrieval/`
- 改名:`eval_retrieval.py` → `retrieval/eval.py`
- 新增:`retrieval/__init__.py`
- 修改 import:`tools.py`、`tests/test_router.py`、`tests/test_compat.py`、`tests/test_retrievers.py`、`scripts/build_eval.py`
- 修改命令与文档:`README.md`、`docs/dev/任务书.md` §14
- 未迁移:`config.py`(全模块共享)、`agent.py`、`tools.py`、`app.py`、`train.py`、`compare.py`、`download_images.py`

## 3. 方案要点

- 只包检索子系统,不搬产品层与 CV 脚本,控制风险;
- 包内模块之间用相对导入(`from . import rag`);
- 保留根级绝对导入 `import config`,因此必须从项目根启动;
- 不保留旧命令的兼容脚本,直接更新文档口径。

## 4. 验收标准与结果

- `python -m unittest discover -s tests`:15 个用例全绿;
- `python -m retrieval.rag --stats`:输出 140 chunks、20 植物;
- `python -m retrieval.eval`:五组指标与包化前一致
  (naive 0.682 / bm25 0.691 / dense 0.518 / hybrid 0.691 / adaptive 0.927);
- 界面与产品链路:纯文字、纯图片、图片+追问均可运行。

## 5. 回滚方案

- 将 `retrieval/` 内四个模块移回根级,`eval.py` 改回 `eval_retrieval.py`;
- 还原 `tools.py`、tests、`scripts/build_eval.py` 的 import;
- 还原 README 与任务书 §14 的命令说明。
