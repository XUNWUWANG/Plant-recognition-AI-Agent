## 1. 变更原因

现有 110 道可答题**全部**包含植物名/别名：

- “不含植物名”的可答题：0 条；
- 40 条 symptom 全部带 `plant_hint`；
- 路由分布：hybrid 77 / bm25 33 / **dense 0**；
- CR-009 的门控中“无植物名”触发 0 次。

也就是说，`dense` 分支、路由的“只描述症状”场景、以及 Agentic 自检，在现有题集上从未被真正验证。必须补一组“用户不知道是什么植物、只描述症状”的题。

- **不动**:现有 120 条主评测集、产品代码、`data/eval/` 其他文件

## 3. 数据设计

### 3.1 规模与类型

- 总数:**60–100,建议 60**;30 条时置信区间过宽,只能当试用集,不足以支撑结论;
- 类型:`symptom` 40 条、`multi`(同时两个症状/诉求)20 条;
- 另设 **unanswerable 扩展 30 条**(与主表 10 条分开报告),用于估计误接收率;
- 每条 `relevant` 1–2 个 chunk,必须存在于当前知识库。

### 3.2 硬性规则

- query 中**不得出现任何植物本名、别名、学名**（含拉丁名），自动校验；
- `plant_hint` 一律为 `null`；
- **必须含足以唯一定位到一种植物的形态/症状线索**，不能只写“叶子发黄”这种 20 种植物都可能成立的问法；
  - 例：“叶子发黄、茎节有气生根、水培瓶里烂根” → 指向绿萝；
  - 标注时额外记录 `target_plant`，仅供校验，**评测代码不得读取/传给检索**；
- 问法自然口语，例如：“叶子发黄还烂根怎么办”“放室内总掉叶子，怎么救”；
- 与 chunk 原文不得连续重合超过 8 字；
- 不引入知识库外的植物或无法回答的问题（后者归 unanswerable）。

### 3.3 校验

`scripts/build_eval.py` 增加 `--blind-check`：

- 无植物名/别名/学名；
- `relevant` id 全部存在；
- 复制重合 ≤ 8 字；
- **唯一性校验**：每条 `target_plant` 与 relevant chunks 的植物一致；由人工判定，再用第二人/模型复核；有歧义的题改写或删除，不得保留；
- 输出类型与数量统计。

### 3.4 样本量与功效

- n=30 时，若命中率约 0.7，标准误约 0.084，95% 置信区间约 ±0.16；
- n=60 时，标准误约 0.059，区间约 ±0.12；
- n=10 的 unanswerable 无法稳定估计误接收率，故扩到 30；
- 本集定位为**可行性证据**，不是统计显著结论；具体区间与配对比较方法见 CR-012，决策规则见 CR-014。

### 3.5 执行分两段（硬约束）

本 CR 必须分两段执行，不得一口气跑完：

| 阶段 | 内容 | 停止条件 |
|---|---|---|
| A 建集 | 写 `blind_queries.jsonl`、跑 `--blind-check`、提交 commit | **到此停止，不得跑评测** |
| B 评测 | 待 CR-014 记录冻结 commit 后，才跑盲题并出表 | 产出对比表与结论 |

顺序必须是：**CR-010 → CR-011(A 建集) → CR-014 冻结 → CR-011(B 评测) → CR-012 → CR-009 → CR-013**。

## 4. 评测方式（阶段 B，CR-014 冻结后）

- 使用 CR-010 的 P1 实体感知协议，但该协议下所有配置都**没有 hint**，实体过滤只能依赖 query 检测（盲题检测不到 → 不生效）；
- 各配置在盲题上全库检索，单独出一张表：
  - Top-1、Recall@5、MRR（附 Wilson 95% 置信区间）；
  - 路由分布（dense 应首次出现）；
  - CR-009 门控触发率与 agentic 结果（若实施）；
- unanswerable 扩展 30 条单独报告误接收率；
- **产物**:`指标/retrieval/盲症状对比表.md`、`指标/retrieval/盲症状错误案例.md`；
- 主表 120 条保持不变，扩展集不并入主表平均；
- **所有结论按 CR-014 预注册的规则判定**，不允许看完结果再改题或改阈值。

## 5. 验收标准

**阶段 A（建集）**

- 数据校验全部通过，无植物名泄漏；
- 唯一性校验通过：每条只有一种合理解释，`target_plant` 与 relevant 一致；
- 类型数量符合 40 symptom + 20 multi + 30 unanswerable 扩展；
- 提交 commit 并记录，随后停止。

**阶段 B（评测）**

- CR-014 已冻结并记录同一 commit；
- `dense` 路由在扩展集上触发次数 > 0；
- 输出扩展集对比表、置信区间与错误案例；
- 按 CR-014 的预注册规则给出明确结论（保留规则 / 改规则 / 负结果）；
- 若 dense 或 agentic 表现不佳，如实记录为负结果，不修改题集去“凑”结论；
- 120 条主表数字不变。
