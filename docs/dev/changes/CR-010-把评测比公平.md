## 1. 变更原因

现有 5 组评测中，只有 adaptive 获得识别结果 `plant_hint` 并启用实体过滤，其余配置传 `None`、全库排序。实测表明：

- `plant_hint` 本身没有影响：adaptive 传 `None` 仍是 0.927，路由分布不变（77 hybrid / 33 bm25）；
- 真正的增益来自**实体过滤**：
  - bm25 0.691 → bm25+filter 0.555 / 0.868 / 0.722；
  - hybrid 0.691 → hybrid+filter 0.682 / 0.932 / 0.824；
  - **dense+filter 0.700 / 0.950 / 0.836，才是 P1 下最强基线**；
- adaptive（0.655 / 0.927 / 0.804）既不优于 hybrid+filter，也不优于 dense+filter。

> 括号内顺序:Top-1 / Recall@5 / MRR。

因此当前表格把“实体过滤 + 路由”的收益全部算在 adaptive 头上，结论不成立。必须重跑公平协议并补消融。

> 表述口径：这不是 adaptive“作弊”，而是**评测协议没有给对照组同等的实体信息**。论文与答辩中应写“协议不对等”，不要写成“adaptive 用了正确答案提示”。
>
> 基线口径：**P1 下的“最强基线”按指标取所有对照的最大值**；当前为 dense+filter（Recall/MRR/Top-1 三项均最高），hybrid+filter 是次强基线，不能把 hybrid+filter 单独称作“最强”。

## 3. 方案要点

### 3.1 两套协议，分开报告

| 协议 | 规则 | 用途 |
|---|---|---|
| P1 实体感知（主表） | 所有配置统一使用“case 的 plant_hint，缺失时从 query 检测”的实体约束 | 回答"系统在有植物信息时谁更好" |
| P2 原五组（辅表） | naive/bm25/dense/hybrid 不加 hint、不做实体过滤；adaptive 为产品路径，自动实体过滤 | 保留与改造前的可比性 |

> P2 不是“全部无过滤”；纯无过滤的对照看 P1 的 `adaptive−filter`。P2 表头必须注明 adaptive 含自动过滤。

禁止只给某一组开过滤。

### 3.2 新增对照与消融

在 P1 协议下新增：

- `dense+filter`：**主基线**（当前三项指标最高）；
- `hybrid+filter`：次强基线；
- `bm25+filter`；
- `adaptive−filter`：保留规则路由，去掉实体过滤；
- `adaptive−retry`：保留路由，关闭质量回退；
- 原 `adaptive`：当前产品路径。

P2 协议保留现有 naive / bm25 / dense / hybrid / adaptive 五组。

### 3.3 指标口径

沿用 CR-012：Top-1 命中率、Recall@5、MRR 分开报；延迟分路线报；路由效用按“相对 P1 最强基线的逐题差值”统计，主基线为 `dense+filter`，同时给出 `hybrid+filter` 的差值。

### 3.4 结论口径

评测完成后必须明确写出以下之一：

- 若 adaptive 在 P1 下优于最强基线：保留“路由提升质量”的表述；
- 若打平或更差：论文主张改为“实体过滤是主要增益；过滤后 dense+filter 三项最高；当前中位延迟也未高于 hybrid/adaptive，路由未显示质量或延迟优势；最终延迟以 CR-012 固定口径复核”。
- 不允许再看 P2 的 adaptive 0.927 就宣称路由有效；
- 也不允许只和 hybrid+filter 比而不报 dense+filter。
