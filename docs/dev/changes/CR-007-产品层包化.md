## 1. 变更原因

根目录仍平铺 `agent.py`、`app.py`;界面代码混合 UI 布局、JS 脚本、初始化与示例数据。包化后根目录只留启动入口,产品层职责清晰。

## 2. 影响范围

- 新增:`plant/__init__.py`、`plant/orchestrator.py`、`plant/render.py`、`plant/ui.py`
- 修改:根 `app.py`(改为入口)、README 目录树、`架构说明.md`
- 删除:`agent.py`(内容迁入 `plant/orchestrator.py`)
- 不动:`retrieval/`、`vision/`、`advice/`、`llm.py`、CV 脚本、`scripts/run_app.cmd`、`.claude/launch.json`

## 3. 方案要点

| 模块 | 内容 |
|---|---|
| `plant/orchestrator.py` | 原 `agent.agent_handle`、`_identify` |
| `plant/render.py` | `FLOWER_LANG`、`_flower_lang`、`_conf_color`、`_render_advice` |
| `plant/ui.py` | Gradio `build()`、`_ROUTE`、CSS、JS、示例图/问题 |
| `app.py` | 仅保留:`from plant.ui import demo` 与 `launch()` |

- `demo` 仍在 import 时构建,保持 `scripts/run_app.cmd` 与 `.claude/launch.json` 不变;
- `python app.py` 命令不变;
- 保持 Markdown 输出与界面行为完全一致。

**不做**:不改 UI 视觉与交互;不引入 Web 框架;不改启动端口。

## 4. 验收标准

- `python app.py` 正常启动,`scripts/run_app.cmd` 正常启动;
- 纯文字、纯图片、图片+追问三条路径输出与改造前一致;
- `python -c "import app"` 成功;`grep -n "agent" app.py` 无结果;
- `python -m unittest discover -s tests` 全绿;
- `python -m retrieval.eval` 五组指标不变;
- 根目录不再存在 `agent.py`。

## 5. 回滚方案

把 `plant/orchestrator.py` 恢复为根 `agent.py`,恢复 `app.py` 原内容,删除 `plant/`;`git revert` 单提交。
