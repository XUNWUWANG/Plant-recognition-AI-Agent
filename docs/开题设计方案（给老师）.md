## 一、选题背景与问题

本课题源自本人前期的植物识别 AI Agent 项目：用户上传植物照片，系统识别植物名称，并从本地知识库检索养护资料，最后由大语言模型组织成养护建议。系统整体已可运行，但**中间检索环节存在明确缺陷**：

- 现有检索采用**字面子串匹配**：要求用户用词与知识库正文一字不差才命中；
- 例如用户问"叶子发黄怎么办"，而知识库写的是"常见问题：叶片失绿、边缘焦枯……"，词面对不上即漏检；
- 检索查询目前只接受"识别出的植物名"，系统尚无自由提问能力，因此检索策略**只有一条路**，无法按问题类型调整。

因此，本课题不改动图像识别（输入）与大模型生成（输出）两端，而是**聚焦中间的检索子系统，进行重新设计与评测**：让系统能理解不同形式的提问，选择合适检索方式，并在检索质量不足时自行纠正。

## 二、研究目标与工作边界

### 2.1 研究目标

1. 为系统增加**自由文本提问**能力（支持纯文字、纯图片、图片+追问三种输入）。
2. 将知识库由"每植物一段"改造为**多主题分块**（光照、浇水、温度、施肥、病虫害、常见问题等）。
3. 设计并实现**三路检索**：BM25 关键词检索、稠密向量语义检索、RRF 结果融合。
4. 设计并实现**自适应路由与检索后纠错**：按问题特征选择检索策略，质量不足时回退换路。
5. 建立**可复现的评测协议**：标注评测集、5 组对照实验、分类型指标与误差分析。

### 2.2 工作边界（明确不做什么）

| 做 | 不做 |
|---|---|
| 检索子系统的数据设计、接口设计、决策流程设计 | 不训练图像识别模型（沿用前期成果） |
| 知识库结构化与分块建模 | 不微调大语言模型（仅调用接口） |
| 检索算法选型、组合与评测 | 不追求算法原创，重点在设计与验证 |
| 可复现的离线评测体系 | 不做多轮对话、多跳检索、查询改写等扩展功能 |

> 本课题的定位是**系统设计与实验评估**，而非算法创新；工作量体现在数据建模、检索决策子系统实现、评测协议设计与误差分析。

## 三、国内外研究基础（简要）

> 以下文献均已逐条核验（核验日期 2026-11-25，核验记录见 `docs/参考文献.md`）。

**英文文献**

[1] JEONG S, BAEK J, CHO S, et al. Adaptive-RAG: learning to adapt retrieval-augmented large language models through question complexity[C]//NAACL 2024. 2024: 7036-7050. DOI: 10.18653/v1/2024.naacl-long.389.
—— 按问题复杂度自适应选择检索策略与检索次数，为本课题"按查询特征选路"提供直接依据。（本课题用可解释特征规则替代原文的复杂度分类器，属工程简化，非复现。）

[2] ASAI A, WU Z, WANG Y, et al. Self-RAG: learning to retrieve, generate, and critique through self-reflection[C]//ICLR 2024. arXiv:2310.11511.
—— 由模型自行判断是否检索、结果是否相关，体现"检索决策"思想。

[3] YAN S Q, GU J C, ZHU Y, et al. Corrective retrieval augmented generation[EB/OL]. arXiv:2401.15884, 2024.
—— 检索后进行质量评估，不满足则更换检索方式，为本课题"检索后回退纠错"提供依据。

[4] CORMACK G V, CLARKE C L A, BÜTTCHER S. Reciprocal rank fusion outperforms Condorcet and individual rank learning methods[C]//SIGIR '09. 2009: 758-759. DOI: 10.1145/1571941.1572114.
—— `1/(k+rank)` 融合公式的出处；原文明确 `k=60` 为预实验选定值。

[5] ROBERTSON S, ZARAGOZA H. The probabilistic relevance framework: BM25 and beyond[J]. Foundations and Trends in Information Retrieval, 2009, 3(4): 333-389.
—— BM25 的理论依据与参数（`k1`、`b`）含义。

[6] LEWIS P, PEREZ E, PIKTUS A, et al. Retrieval-augmented generation for knowledge-intensive NLP tasks[C]//NeurIPS 2020. 2020: 9459-9474. arXiv:2005.11401.
—— RAG 基本思想（参数化 + 非参数化记忆）的出处。

[7] MUENNIGHOFF N, TAZI N, MAGNE L, et al. MTEB: massive text embedding benchmark[C]//EACL 2023. 2023: 2006-2029. DOI: 10.18653/v1/2023.eacl-main.148.
—— 向量模型选型有公开评测基准。

[8] ZHANG Y, LI M, LONG D, et al. Qwen3 embedding: advancing text embedding and reranking through foundation models[EB/OL]. arXiv:2506.05176, 2025.
—— 本课题所用向量模型（Qwen3-Embedding-0.6B）的出处；该系列提供 0.6B/4B/8B 三档并支持查询指令。

**中文文献**

[9] 卞佳兴. 面向高校规章制度的融合混合检索与置信拒答的智能问答方法研究[J]. 无线互联科技, 2026(12): 79-82.
—— 与本课题场景相近的中文知识库问答工程验证：BM25 + 向量混合检索、重排与置信拒答；其报告中 F1=0.324、MRR=0.781（另有"综合正确率 96.9%"，系不同指标，不可与 F1 混用）。

> 说明：上述文献仅作为设计依据。本课题采用**可解释的特征规则 + 检索质量回退**的工程化实现，并在中文植物养护场景自建评测集，不以复现原论文为目标。

## 四、系统总体设计

系统按职责分为四层，层间以稳定接口通信，便于单独评测与替换：

```
┌─────────────┐   ┌──────────────┐   ┌──────────────┐   ┌──────────────┐
│ 输入层       │   │ 检索层        │   │ 决策层        │   │ 生成层        │
│ 图片 / 文本  │──▶│ BM25 / 向量   │──▶│ 路由 + 回退   │──▶│ 大模型生成    │
│（沿用前期）  │   │ 索引与融合    │   │ 决策与纠错    │   │（调用接口）   │
└─────────────┘   └──────────────┘   └──────────────┘   └──────────────┘
        ▲                                                      │
        └────────────────── 评测层（离线，零外部调用）─────────┘
```

**设计原则**：

1. **可测试性优先**：检索与决策可脱离界面、脱离大模型独立评测。
2. **接口稳定**：检索入口签名扩展后保持返回格式不变，下游无需改动。
3. **可回退**：任一策略失效时保留原朴素检索作为兜底。

## 五、数据设计（重点）

### 5.1 概念模型（E-R）

```
植物 Plant 1 ──── N 知识片段 Chunk
评测样本 EvalCase N ──── N 知识片段 Chunk   （通过相关性表关联）
评测样本 EvalCase 1 ──── N 检索轨迹 RouteTrace
实验批次 EvalRun 1 ──── N 单题结果 CaseResult
```

### 5.2 逻辑设计（表结构）

| 表 | 主要字段 | 说明 |
|---|---|---|
| `knowledge_chunk` | `chunk_id`(PK)、plant、section、text、source、updated_at | 知识片段，主键为"植物#小节" |
| `eval_case` | `case_id`(PK)、query、type、difficulty、plant_hint | 评测问题及类型 |
| `eval_relevance` | `case_id`(FK)、`chunk_id`(FK)、grade | 问题—片段相关性（多对多） |
| `route_trace` | `trace_id`(PK)、case_id(FK)、route、retried、top1_score、latency_ms | 每次检索决策轨迹，用于误差分析 |
| `eval_run` | `run_id`(PK)、config、recall5、mrr、latency_med、latency_p95 | 一次实验的汇总结果 |

### 5.3 物理设计

| 数据 | 存储方式 | 说明 |
|---|---|---|
| 知识库主数据 | 文本文件（人工维护） | 单一数据源 |
| 分块结果 | `chunks.json` | 由主数据解析生成的物化结果 |
| 关键词索引 | 内存倒排（jieba 分词 + BM25） | 启动时构建 |
| 向量索引 | `emb_*.npz`（向量矩阵 + 内容哈希） | 首次构建后缓存 |
| 评测日志 | SQLite（三张表） | 可查询、可复现 |

### 5.4 一致性与失效设计

- 主数据与派生数据分离：知识库变更后，依据**内容哈希**自动重建分块与向量缓存；
- 派生数据可随时丢弃重建，不丢失原始信息；
- 评测日志与实验批次绑定，保证结果可追溯。

> 说明：本课题未使用数据库管理系统，但实现了**等价的数据建模要素**：实体、主键、外键、索引、缓存与失效策略；评测日志使用 SQLite，可按问题类型回溯检索决策。

## 六、接口设计

| 接口 | 输入 / 输出 | 设计意图 |
|---|---|---|
| `retrieve(query, topk, plant_hint)` | 问题、条数、植物名提示 → 文本片段列表 | 下游无感，兼容原有调用 |
| `router.decide(query, plant_hint)` | 问题特征 → 检索路线 | 纯函数，可单测、可解释 |
| `router.should_retry(...)` | 检索结果质量 → 新路线或空 | 纠错机制的唯一入口 |
| `eval.run(configs)` | 实验配置 → 指标表 + 日志 | 可复现、可对比 |

设计要点：**接口稳定优先于实现变化**；检索决策与融合逻辑封装在内部，输入输出契约保持不变。

## 七、检索与路由设计

### 7.1 三路检索

| 路线 | 方法 | 适用场景 |
|---|---|---|
| 关键词 | BM25（`k1=1.5, b=0.75`），中文 jieba 分词 | 植物名、别名、学名等精确词 |
| 语义 | 稠密向量（Qwen3-Embedding-0.6B），查询加任务指令 | 口语化症状描述、用词不一致 |
| 融合 | RRF（`k=60`），两路各取前 10 融合 | 需同时满足"锁定植物"与"理解描述" |

### 7.2 路由决策表

| 查询特征 | 路线 | 理由 |
|---|---|---|
| 无问题、仅有植物名 | BM25 | 精确词匹配最稳 |
| 含植物名/别名，无症状词 | BM25 | 同上 |
| 含植物名 + 症状词 | 混合 | 既需锁定植物，又需理解症状 |
| 仅含别名/学名 | 混合 | 别名精确 + 语义兜底 |
| 仅含症状/意图词 | 向量 | 口语与文档用词不一致 |
| 其他 | 混合 | 保守策略 |

### 7.3 检索后回退（纠错）

- BM25：若查询关键内容词在首条结果的**覆盖率**低于阈值，则改走混合检索；
- 向量：若首条相似度低于阈值，则改走混合检索；
- 混合：不再回退，避免循环。

## 八、实验设计

### 8.1 评测数据

- 规模：120 条标注问题，分 5 类——点名型 30、症状型 40、别名型 25、多意图型 15、知识库外 10；
- 构建方式：由知识片段半自动出题，再逐条人工改写为真实问法，并标注相关片段；
- **防泄漏**：问题不得照抄知识库原文，不得使用评测集调参。

### 8.2 对照组

| 组 | 说明 |
|---|---|
| 基线 0 | 原朴素字面匹配（迁移到分块粒度，公平对照） |
| 基线 1 | 纯 BM25 |
| 基线 2 | 纯向量 |
| 基线 3 | 固定混合（BM25+向量+RRF） |
| 本文方法 | 自适应路由 + 回退纠错 |

### 8.3 指标

- **Recall@5**：前 5 条命中相关片段的比例；
- **MRR**：首个相关结果排名的倒数均值；
- **检索延迟**：单次检索中位数与 P95（不含首次索引构建）；
- **路由准确率**：所选路线达到该题最优路线效果的占比；
- **分层报告**：按问题类型分别统计；
- **知识库外问题**：单独统计首条结果的覆盖度与相似度，观察系统置信度是否下降。

## 十一、风险与应对

| 风险 | 应对措施 |
|---|---|
| 知识库规模较小，检索差异不显著 | 先做可行性判据实验；必要时增加分块粒度与干扰片段 |

| 路由规则在真实提问上表现不稳 | 以误差分析驱动规则迭代；不改动评测集 |
| 与前期项目区分不清 | 明确边界：本次工作仅涉及检索子系统，图像识别与界面为前期成果 |
| 时间与考研复习冲突 | 设计方案先行锁定，开发集中在初试后；范围已做裁剪 |
